## Trigger

| Option | Description | Selected |
|--------|-------------|----------|
| URL как источник правды | Эффект ключуется на `?q`; и шапка, и «Найти» пишут `?q`; StrictMode-двойник гасится сравнением с последним выполненным q | ✓ |
| Одноразовый маркер в `location.state` | Страница потребляет маркер и снимает через `replace`; `?q` только заполняет поле; F5/шара даёт pre-search | |
| Шапка сама выполняет `searchKnowledge` | Результаты едут состоянием навигации; страница не грузит на mount | |

**User's choice:** URL как источник правды.
**Notes:** Причина — `?q` уже контракт шапки и уже читается страницей; вариант «шапка сама ищет» продублировал бы `runSearch` (валидация, роль, `limit/offset`, ошибки, `trackGoal`) в компоненте шапки.

| Option | Description | Selected |
|--------|-------------|----------|
| `replace` | Адрес всегда равен текущему запросу, каждый поиск не создаёт шаг истории, Back уводит со страницы | ✓ |
| `push` | Каждый поиск — шаг истории, Back возвращает предыдущий запрос | |
| Нет | Форма остаётся локальной, URL обновляет только шапка | |

**User's choice:** `replace`.
**Notes:** Без записи из формы адрес перестаёт быть источником правды и F5 теряет введённый запрос.

## Back/forward and repeat submit

| Option | Description | Selected |
|--------|-------------|----------|
| Модульный in-memory кэш | Последний результат по паре `(q, role)`, Back/Forward восстанавливает без запроса, F5 всегда идёт в API, storage не используется | ✓ |
| Без кэша | Каждая навигация на `?q=` — ровно один запрос; критерий 3 читаем узко, Back переиспускает запрос | |
| `sessionStorage`-кэш | Переживает F5 и remount, но появляется persist-слой и риск устаревших результатов | |

**User's choice:** Модульный in-memory кэш.
**Notes:** `KnowledgePage` размонтируется при уходе на материал (соседние маршруты `/knowledge` и `/materials/:id`), поэтому ref внутри компонента критерий 3 не выполняет.

| Option | Description | Selected |
|--------|-------------|----------|
| Всегда свежий запрос | Тот же q тоже переисполняется; шапка кладёт одноразовый `submitId` в `location.state`, страница снимает его через `replace` | ✓ |
| No-op | Тот же q — URL не изменился, ни запроса, ни спиннера | |
| Из кэша | Результаты уже на экране, запрос не нужен | |

**User's choice:** Всегда свежий запрос.
**Notes:** Семантика «Найти» на странице не меняется; кэш не должен обслуживать явную отправку.

## Header contract with the form

| Option | Description | Selected |
|--------|-------------|----------|
| Сброс на «Все» | Отправка из шапки — новый поиск с чистого листа; роль не сужает выдачу незаметно | ✓ |
| Сохранить текущую роль | Шапка уважает уже выбранную роль | |
| Роль в URL | `?q=…&role=ds`, единый источник правды для обоих фильтров | |

**User's choice:** Сброс на «Все».
**Notes:** Поведение должно быть одинаковым из любого раздела и при любом mount.

| Option | Description | Selected |
|--------|-------------|----------|
| Нейтральный pre-search лендинг | Без ошибки, чипы-подсказки по D-60 на месте, guard «Введите запрос» остаётся у кнопки «Найти» | ✓ |
| Inline «Введите запрос» сразу | Явная обратная связь, что отправка не сработала | |

**User's choice:** Нейтральный pre-search лендинг.
**Notes:** Пустая отправка трактуется как «просто открыть Базу знаний».

| Option | Description | Selected |
|--------|-------------|----------|
| Навигация + inline «Сократите запрос» | Один путь валидации через `validateKnowledgeQuery`, ноль запросов | ✓ |
| `maxLength={500}` в шапке | Браузер молча режет ввод, inline-guard недостижим из шапки | |
| Своя ошибка в шапке | Второй путь валидации и вторая копия текста | |

**User's choice:** Навигация + inline «Сократите запрос».

## Claude's Discretion

- **Инструмент доказательства критерия 2.** Пользователь отказался обсуждать зону отдельно и выбрал «Готов писать CONTEXT.md». Зафиксировано в CONTEXT.md как discretion с явным конфликтом: `VITE_USE_MOCKS=true` делает HTTP-перехват холостым, дефолт — невакуумный харнесс-счётчик на границе `searchKnowledge`; live-режим с `page.route` допустим только как отдельный spec с обоснованием.
- Форма кэша (модуль страницы против `knowledgeApi.js`, состав снимка — не терять «Показать ещё»).
- Точка потребления `submitId` и отличение навигации из истории от новой отправки.
- Дом тестов (`tests/web-app.spec.js` против `tests/knowledge.spec.js`) и, при новом файле, расширение `testMatch`.
- Нормализация/кодирование `?q` и защита от второго запроса на тот же смысл.
- Поведение ошибки относительно кэша (ошибка не кэшируется).

## Deferred Ideas

- Роль в URL (`?q=…&role=ds`) — расширение контракта адреса.
- `sessionStorage`/`localStorage`-кэш результатов — persist-слой и риск устаревших данных.
- `maxlength` в поле шапки — молчаливое обрезание ввода.
- Кнопка/авто-обновление выдачи, polling свежести — новая функциональность.
- Серверная аналитика поиска / метрики «поиск на загрузке» — вне скоупа REQUIREMENTS.
