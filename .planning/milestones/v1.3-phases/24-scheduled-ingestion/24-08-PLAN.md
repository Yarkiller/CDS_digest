# Phase 24 Plan 08 — Gap closure G-24-4: the alert must read the numeric exit status

<objective>
Make `deploy/systemd/digest-ingest-alert.service` read the numeric exit status from `MONITOR_EXIT_STATUS` (with an `EXIT_STATUS` fallback) instead of the `exited`/`killed` qualifier in `MONITOR_EXIT_CODE`, invert the text contract so the broken substitution can never return, correct the docs that claim the distinction works, and prove on a live systemd host that forcing exit 1 and exit 2 produces two different alert lines.

Purpose: UAT test 4 observed both exit 1 and exit 2 producing «digest-ingest.service failed: unexpected failure (exit exited)». On systemd 255 the failing unit's environment provides `MONITOR_EXIT_CODE=exited` (a qualifier) and `MONITOR_EXIT_STATUS=2` (the number); `EXIT_CODE`/`EXIT_STATUS` are unset. The old expression therefore never fed a number to the `case`, so threat T-24-34 (operators can tell *why* nothing arrived) was not closed (G-24-4).

Output: one corrected `ExecStart=` line, an inverted plus extended alert check in `tests/unit/test_phase24_systemd_units.py`, a runbook §5e item 8 live recipe, and corrected SECURITY/VERIFICATION records.
</objective>
