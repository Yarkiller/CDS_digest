## Команда сбора и контракт вывода

### Форма команды

| Option | Description | Selected |
|--------|-------------|----------|
| Отдельный entry point `ingest-collect` | Новый модуль + `[project.scripts]`; `cli.py` не меняется, трипваер `test_cli_ingest_contract.py` не может сломаться | ✓ |
| Флаг `--all-sources` на существующей команде | Одна точка входа, но две ветки в файле, который запирает stdout-контракт | |
| Typer-группа с подкомандой `collect` | Семантически красиво, но форма вызова зависит от тонкостей Typer — высокий риск для трипваера | |

**User's choice:** Отдельный entry point `ingest-collect`
**Notes:** Причина — Typer-приложение из одной команды перестаёт принимать `ingest <url>` без имени подкоманды, если добавить вторую команду в тот же `app`.

### Шаблон статьи

| Option | Description | Selected |

| Жёстко `lecture` в коде | Смена шаблона = правка кода и релиз | |

**User's choice:** Env `INGEST_TEMPLATE`

### Контракт вывода

| Option | Description | Selected |
|--------|-------------|----------|
| JSON-сводка в stdout + per-video в stderr | Проще для будущей автоматизации | |
| Человекочитаемая сводка в stdout | Детали в stderr, читаемо оператором через journalctl | ✓ |
| Всё в stderr, stdout пустой | Безопасно, но противоречит разделению «stdout — результат» | |

**User's choice:** Человекочитаемая сводка в stdout
**Notes:** Побочное следствие — per-video checkmarks `run_ingest_pipeline` не должны попадать в stdout.

### Лимит видео за прогон

| Option | Description | Selected |
|--------|-------------|----------|

### Порядок обработки

| Option | Description | Selected |

## High-water mark

### Где хранится

| Option | Description | Selected |
|--------|-------------|----------|
| Колонки на `pipeline_ingest_sources` | Миграция 013; удаление источника уносит курсор; один SELECT на прогон | ✓ |
| Отдельная таблица курсоров | Чистое разделение, но лишний join и вторая RLS-поверхность | |
| Локальный файл на VM | Состояние вне БД; ломается при переезде, два writer'а расходятся | |

**User's choice:** Колонки на `pipeline_ingest_sources`

### Семантика границы

| Option | Description | Selected |
|--------|-------------|----------|
| `published_at` из фида + тай-брейк `video_id` | Фид отдаёт `published` для каждой записи | ✓ |
| Только `last_seen_video_id` | Ломается при удалении видео из ленты или выпадении из окна 15 записей | |
| Не хранить курсор, сверять с `materials` | Лишние чтения БД; ING-05 выполняется лишь частично | |

**User's choice:** `published_at` + тай-брейк

### Первый прогон источника

| Option | Description | Selected |
|--------|-------------|----------|
| Обработать всё окно фида в пределах лимита | Включение источника приносит драфты | ✓ |
| Только инициализировать курсор | Админ не получает ни одного драфта — сломанное ожидание | |
| Пропустить самый новый entry | Избыточно для YouTube-фида | |

**User's choice:** Обработать всё окно фида

### Упавшее видео и курсор

| Option | Description | Selected |
|--------|-------------|----------|
| Не двигать дальше упавшего — ретраить завтра | Надёжно, но вечно битое видео переплачивает captions каждый день | |
| Пропустить упавшее, курсор двигать дальше | Батч доходит до конца окна; видео теряется молча | ✓ |
| Ретраить только транзиентные ошибки | Требует классификации причин отказа — больше логики | |

**User's choice:** Пропустить упавшее, курсор двигать дальше
**Notes:** Принятая цена — молчаливая потеря, поэтому видимость пропуска вынесена в отчёт (stderr + счётчик `failed`) и в ручной путь ретрая.

### Границы изоляции

### Exit code

| Option | Description | Selected |
