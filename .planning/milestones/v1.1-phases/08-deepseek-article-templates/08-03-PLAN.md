<objective>
Fail closed when a transcript exceeds the character budget, and fail at startup when the cap is not a positive integer or a template file cannot be read. Neither case adds an IngestError stage.

Purpose: Oversized transcripts never reach DeepSeek, and operators can tell a local policy reject from a provider context-length rejection.
Output: ArticleBudgetError on process, llm_truncation mapping, ConfigurationError for a bad cap, and TemplateLoadError.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Transcript.text length → process | Untrusted size. The injected integer is the only budget |
| MAX_TRANSCRIPT_CHARS env → Settings.from_env | Invalid values die at startup as ConfigurationError |
| Template files → loader | Missing or unreadable files die before the HTTP client exists |
| ArticleBudgetError → operator JSON | Context is two integers |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-08-CAP | Denial / disclosure | `DeepSeekArticleGenerator.process` | high | mitigate | len(transcript.text) greater than the injected cap raises ArticleBudgetError before create. No silent slice. Template characters do not count (D-08, ASVS V5) |
| T-08-CTX | Information disclosure | `llm_truncation` context | high | mitigate | Context is exactly char_count and max_chars. No transcript text and no video_id (D-09) |
| T-08-CONFIG | Tampering | `Settings.from_env` | medium | mitigate | Non-integer, zero, and negative MAX_TRANSCRIPT_CHARS raise ConfigurationError, not a fake llm_truncation (D-07) |
