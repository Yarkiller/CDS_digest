## Root cause (G-14-1 / G-14-4)

`_fetch_one` (material_repository.py ~128-146) selects:

```text
... material_tags(tag_slug,tag_label), material_relations(to_material_id)
```

`material_relations` has two FKs into `materials` (`from_material_id` line 117, `to_material_id` line 118 of 001_initial_schema.sql), so the un-hinted embed is ambiguous → `postgrest.exceptions.APIError` PGRST201 → wrapped in `PersistenceError` → single route maps to HTTP 503 `materials_unavailable`; the batch route maps every id to `{ok:false, error:"materials_unavailable"}` under HTTP 200. `material_tags` has a single FK (line 110) and needs no hint.
