## Copywriting Contract

All copy is **Russian**, calm editorial/ops tone. Carry forward Phase 5 / 13 admin copy unless superseded below. **Never** invent `score_factors` / factor labels. **Never** auto-ready on Approve (D-02).

| Element | Copy |
|---------|------|
| Primary CTA (phase focal) | **«Сделать ready»** — per-row, next to draft badge only when `material_status === 'draft'` (D-01) |
| Batch CTA | **«Сделать ready одобренные черновики»** — visible **only** when `approvedDrafts.length > 0` (D-03); hidden otherwise |
| Soft empty-body warn (per-row only) | **«Текст пуст. Сделать ready и продолжить?»** — `window.confirm`; Cancel aborts; OK proceeds (D-04/D-10) **[discretion]** |
| Batch confirmation | **«Сделать ready N одобренных черновиков?»** where `N = approvedDrafts.length` — confirm only for batch (D-04). Do **not** list full titles in the confirm string (titles already listed under send hint). Cancel aborts. **[discretion: count, not titles]** |
| Empty «Обоснование» (exact) | **`Обоснование недоступно — скоринг не запускался`** — shortlist row only; muted; when `factor_labels` usable count &lt; 2 (D-15/D-16/D-17). Playwright + mocks assert **exact** string. |
| Populated «Обоснование» | Unchanged Phase 5: join real `factor_labels` with ` · ` — never fabricate (D-13) |
| Optimistic ready badge | Show **`ready`** immediately after successful promote (per-row or batch ok ids); silent shortlist refetch (D-05) |
| Partial-batch failure toast | Reuse existing decision partial-failure toast pattern — name failed ids/titles; do not invent success chrome |
| Empty state (shortlist) | Unchanged: **«Кандидатов пока нет»** / **«Обновите список позже.»** — out of Phase 14 delta |
| Error state (promote) | Per-row / batch API failure → existing admin toast / keep draft badge; no fake ready. Single not-found follows API error path. |
| Destructive confirmation | **none** — Phase 14 has no destructive wipe; ready is reversible only in a later phase (ready→draft deferred) |
| Approve / Reject labels | Unchanged **«Одобрить выбранные»** / **«Отклонить выбранные»** — must **not** imply ready |

**Interaction rules (ADUX-05):**
1. Per-row «Сделать ready» sits **inline next to the draft badge** in the status meta row — **not** inside the Approve/Reject toolbar cluster (D-01: state ≠ decision).
2. Per-row: **one-click** when body non-empty; soft confirm only when body empty/missing (D-04/D-10).
3. After promote: optimistic `draft` → `ready` + silent `fetchShortlist` (D-05). Hide per-row CTA once status is ready.
4. Batch: one API call (not FE-loop); confirm dialog first; partial success updates ok ids optimistically.
5. Approve must leave `material_status` as draft (D-02) — no UI that couples Approve to ready.

**Honesty rules (ADUX-06):**
1. FE displays only server `factor_labels`; never invent defaults like «релевантность» (D-13).
2. Empty copy is content-muted, not danger/error styling (D-16).
3. Material preview modal does **not** gain factor UI this phase (deferred).

- Confirm with count copy above; then call batch API once.

- `data-testid` recommendation: `admin-mark-ready-batch`.
