## Root cause (G-14-2)

`promoteReady` optimistically sets `material_status: 'ready'`, then `markReady` returns a refetched shortlist DTO and `applyBatch(dto)` overwrites `items` from `dto.items` unconditionally. When the refetched shortlist still reports `draft` (live read-after-write lag, or a backend that acknowledged the POST without persisting), the badge silently reverts — no toast, no error. The mock path masks this because `applyMockMarkReady` mutates the in-memory seed before `cloneBatch()`, so its reconcile always returns `ready`.

The single-ready backend route (`POST /admin/materials/{id}/ready`, admin.py ~272-297) already returns `MarkReadyResponse { material_id, status }` — that response, not a shortlist refetch, is the authoritative promote result.
