## Decision: unhook the FE batch plumbing, retain the backend batch contract

- **Removed (behavior + display):** the `admin-mark-ready-batch` button block, the `promoteApprovedDrafts` handler, the `markReadyBatch` import in `AdminDigestPage.jsx`, and the `sendHint` draft branch.
- **Retained but unhooked (no UI caller):** FE `markReadyBatch` + `applyMockMarkReadyBatch` + the batch call counter/harness in `adminApi.js` / `adminReadyMock.js` / `main.jsx`, and the backend `POST /admin/materials/ready` route + `mark_materials_ready` use-case + DTOs.
- **Rationale:** D-08 (one batch endpoint, partial success) is a locked Phase 14 decision and the backend path is covered by HTTP unit tests (`test_http_admin.py`); deleting it would violate the locked decision and reduce coverage. The operator's request is about the admin UI control, so only the UI entry point is removed. Keeping the FE client + mock helper preserves the tested client↔endpoint contract for the retained route; deleting them would cascade into `main.jsx` and three test files for no product gain.
- **Not removed:** the per-row «Сделать ready» control and `sendUnlocked`'s `approvedDrafts.length === 0` requirement (D-85).
