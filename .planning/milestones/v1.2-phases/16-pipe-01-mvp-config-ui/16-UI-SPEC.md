## Decisions surfaced (must be locked by discuss/plan before execution)

Phase 16 has **no `16-CONTEXT.md` and no `16-RESEARCH.md`** at the time of authoring. Two product decisions are genuinely undecided and are **not** answered by `REQUIREMENTS.md` / `ROADMAP.md`. This contract states an explicit **ASSUMED** value for each so it is actionable, and flags them as decisions the discuss/plan phase must confirm or override. Neither is silently picked.

| # | Question | Contract ASSUMPTION (flag: lock before execute) | Why this default |
|---|----------|---------------------------------------------------|------------------|
| A-1 | **Representation:** raw YAML text editor vs structured field form vs hybrid? | **Raw YAML** in a single monospace `<textarea>` (source of truth is the YAML document). No structured field builder in MVP. | `CONTEXT.md` domain language says Админ «управляет YAML-конфигами»; `ROADMAP.md` says «View/edit/validate/persist pipeline **YAML**». Raw YAML is the smallest thing that satisfies PIPE-01 MVP; a structured builder multiplies schema/form surface and can land later. **If the discuss phase picks structured fields, this contract's editor section is replaced but spacing/typography/color/copy rules still hold.** |
| A-2 | ~~**Route + nav placement:** where does the surface live?~~ **SUPERSEDED by ADUX-12 / Phase 22** — see `.planning/phases/22-admin-nav-grouping/22-UI-SPEC.md`. | **Route `/admin/pipeline` retained** (no new route). AppShell keeps a **single** `Админ`-gated entry **«Админ»** → `/admin/digest`; the two admin sections switch through **in-page** underline tabs «Дайджест \| Пайплайн» rendered by `AdminLayout` for `/admin/digest` + `/admin/pipeline` only. Digest send flow stays isolated; `/admin/materials/:id` stays a sibling without the tab row. | The original assumption (a second top-level AppShell item «Пайплайн») is retired by ADUX-12 / Phase 22. «Do not add a second navigation bar» **still holds** because the tab row is in-page content, not shell chrome (D-05). |

**No execution UI:** this phase ships **no** run / trigger / scheduler / «Запустить» control anywhere. Execution is `PIPE-EXEC-*` (v1.3). This is a hard contract rule (see Page & Component Contracts → Out of scope UI).

**Architectural UI boundary (PIPE-03):** the UI talks **only** through `web/src/services/pipelineConfigApi.js`. It must not import Supabase, SQL, or storage internals. Storage lives behind a port (`PipelineConfigRepository`) owned by `backend`/`supabase-integration` and wired in `composition/`. The SPA consumes a JSON DTO (`{ yaml, updated_at }` on read; structured errors on reject). This boundary is a design-contract requirement, not just an architecture-rule nicety.

**Interaction rules (PIPE-01 / PIPE-02 / PIPE-03):**
1. **View** (PIPE-01): on mount, GET the config; render YAML into the editor. Empty (no saved config) → Empty state above; populated → editor with content.
2. **Edit** (PIPE-01): the editor is a raw `font-mono` `<textarea>`; edits set `dirty = true` and enable Save + «Отменить изменения».
3. **Validate-before-save** (PIPE-02): the **server is authoritative**. On save, `PUT` the YAML. A valid config returns 200; an invalid config is **rejected before persist** with a structured-error payload. The UI renders every error and keeps the document dirty — **never** a silent accept, never a client-only "looks fine" pass.
4. **Persist + reload** (PIPE-03): a successful save clears `dirty`, shows **«Сохранено»**, and the value is readable on the next session (GET returns it). Storage is behind a port; the UI never talks to Supabase.
5. **No execution**: no control in this surface triggers, schedules, or runs the pipeline.

**Error payload contract (UI consumes, backend owns):**
```
{ "errors": [ { "path": "source.playlist", "line": 12, "message": "..." } ] }
```
UI requirements: render one row per error in the summary list; echo `path` / `Строка {line}` in mono; prefix the editor heading with the summary heading; set `aria-invalid` on the editor and `role="alert"` on the panel. Missing `errors` → generic fallback copy.

## Page & Component Contracts

### Route, page & nav (PIPE-01, assumption A-2) — **nav superseded by ADUX-12 / Phase 22**
- Route `/admin/pipeline` is **retained** and rendered by `web/src/pages/AdminPipelineConfigPage.jsx`, nested inside the existing auth-gated `<Route element={<RequireAuth><AppShell /></RequireAuth>}>` block in `App.jsx` (pathless `AdminLayout` parent for `admin/digest` + `admin/pipeline`).
- ~~`AppShell.jsx` gains one `Админ`-gated nav item **«Пайплайн»** (`appRole === 'admin'`), matching the existing `linkClass` pill.~~ **Obsolete (ADUX-12 / Phase 22):** AppShell has exactly one admin-gated pill **«Админ»** → `/admin/digest`, active on any `/admin/*`. Sections switch through in-page underline tabs «Дайджест | Пайплайн» in `AdminLayout` (`nav aria-label="Разделы админки"`), collapsing to a native `<select>` below `sm` that navigates via `navigate()` so the Phase 19 leave guard still fires.
- **«Do not add a second navigation bar» remains true (D-05):** the tab row is in-page content in the page column, not AppShell chrome; it uses underlines, never pill fills.
- Page shell: `<section data-testid="admin-pipeline-page">` … the page H1 «Конфиг пайплайна» and the duplicated eyebrow are **removed** (D-06); the active in-page tab carries the H1 weight. Toolbar + editor panel unchanged. `pb-32` not required (no sticky send footer here).
- Non-admin → `ForbiddenPage`; role-load failure → `ServiceUnavailable` (reuse Phase 5 patterns).

### Config loader (PIPE-01 / PIPE-03)
- `web/src/services/pipelineConfigApi.js` exposes `fetchPipelineConfig()` and `savePipelineConfig(yaml)`, following the `adminApi.js` shape (`AdminApiError`-style error with `code` / `retryable`; mock/live cutover via `isMocksEnabled()`; never silent mock fallback after live failure).
- **UI boundary:** this module is the only place that knows the transport. No Supabase import, no SQL, no storage SDK in components. The DTO is `{ yaml: string, updated_at: string | null }`.
- Load states: `loading` | `ready` | `empty` | `error`.
  - `loading` → `aria-busy="true"` + «Загрузка…».
  - `empty` → Empty state block (`data-testid="pipeline-config-empty"`) + the (empty) editor; Save disabled until non-empty.
  - `error` → `ServiceUnavailable`-style retry with **«Повторить загрузку»** (`data-testid="pipeline-config-retry"`), reuse `service-unavailable` testid if convenient.
- `data-testid` recommendations: `admin-pipeline-page`, `pipeline-config-loading`, `pipeline-config-empty`.

### Editor (PIPE-01)
- Single controlled `<textarea data-testid="pipeline-config-editor">`.
- Classes: `font-mono text-base leading-relaxed text-ink-2`, `min-h-[20rem] max-h-[60vh] w-full overflow-auto rounded-xl border border-rule bg-paper p-3`, `focus-visible:outline-accent` (or existing focus pattern).
- Attributes: `spellCheck={false}`, `autoComplete="off"`, `autoCorrect="off"`, `autoCapitalize="off"`, `wrap="off"` (horizontal scroll for long lines), `aria-label="YAML конфига пайплайна"`, `aria-invalid={Boolean(errors.length)}`.
- On change → `dirty = true`, clear the previous validation-error panel for the live document (stale errors must not stay after an edit).
- Long/overflow config: scrolls inside the editor; never grows the page past the toolbar. Tab inserts focus (do not hijack Tab unless a tab-key handler is explicitly in scope — leave default browser behavior for MVP).

### Toolbar (PIPE-01 / PIPE-02 / PIPE-03)
- Row: primary **«Сохранить конфиг»** (`data-testid="pipeline-config-save"`, solid accent, `min-h-11`, disabled while `!dirty || saving`) + secondary **«Отменить изменения»** (`data-testid="pipeline-config-reload"`, outlined, disabled while `!dirty`, confirms when dirty) + status caption area.
- Status caption (`data-testid="pipeline-config-status"`): shows one of
  - `saving` → «Сохранение…»
  - `saved`/clean → **«Сохранено»** (success tint) or **«Изменений нет»** when untouched
  - `failed` → inline failure text (panel handled by `ErrorPanel`)
- Saving state: disable both controls; `aria-busy` on the toolbar; no layout shift.

### Validation error panel (PIPE-02)
- Rendered directly **above** the editor whenever the last save was rejected. `data-testid="pipeline-config-errors"`, `role="alert"`.
- Heading = Subhead size **«Проверьте конфиг перед сохранением»**.
- Each error row: `data-testid="pipeline-config-error"`, `text-sm text-[oklch(45%_0.14_25)]`, with the mono `Строка {line}` / `{path}` prefix. Ordered list, `space-y-2`.
- Fallback: if the reject carries no `errors`, render the single generic string **«Конфиг не прошёл проверку»**.
- The editor stays editable and **dirty** after a reject — the operator fixes and re-saves; the document is never discarded or auto-reverted.

### Save failure (PIPE-02 / PIPE-03)
- Network / 5xx → `ErrorPanel` with **«Конфиг не сохранён»** + **«Повторить сохранение»** (`data-testid="pipeline-config-save-retry"`). Document stays dirty; nothing is persisted silently.

### Unsaved-changes guard
- Navigating away (or resetting) while `dirty` → `window.confirm('Есть несохранённые изменения. Уйти без сохранения?')`. Cancel aborts. Acceptable for MVP; an in-app dialog can replace it later (mirrors Phase 14 `window.confirm` disposition).
- Reset confirm: `window.confirm('Отменить изменения и вернуть последнюю сохранённую версию?')`.

### Out of scope UI (hard boundary)
- **No** run / trigger / scheduler / «Запустить» / «Выполнить» / schedule-picker control (PIPE-EXEC-* → v1.3).
- **No** config history/version list, diff viewer, or rollback UI.
- **No** structured field builder (unless A-1 is re-decided by discuss).
- **No** secret/credential fields display — if any config value is sensitive, the backend redacts it in the DTO; the UI never renders secrets.
- **No** deep Supabase coupling in the SPA (PIPE-03).
