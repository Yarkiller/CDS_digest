## Spacing Scale

Reuse the locked rem token scale (base 16px). Do **not** add new spacing values.

| Token | Value | px | Usage in this phase |
|-------|-------|----|---------------------|
| xs / `--space-1` | 0.25rem | 4px | Inline gaps inside counts row |
| sm / `--space-2` | 0.5rem | 8px | Hint → textarea gap; provenance → counts |
| md / `--space-4` | 1rem | 16px | Modal section rhythm (title → body blocks) |
| lg / `--space-6` | 1.5rem | 24px | Modal interior padding continuity with Phase 5 |
| xl / `--space-8` | 2rem | 32px | Modal dialog padding on wide viewports |
| 2xl / `--space-12` | 3rem | 48px | Not required on Phase 13 deltas |
| 3xl / `--space-16` | 4rem | 64px | Not required on Phase 13 deltas |

**Continuity tokens (not new inventions):** `--space-3` (12px), `--space-5` (20px) — reuse from Phase 5 / `tokens.css` for modal header/body rhythm only.

Exceptions:
- **44px minimum touch target** on modal close (`✕`), reader-link control, email preview retry — Phase 5 a11y lock.
- Material modal body region: **scroll inside dialog** (`max-h-[90vh]` panel already); body prose scrolls with the panel — do not nest a second scroll unless overflow demands it.
- Email iframe: `min-h-64` (256px) minimum preview height; grow with modal scroll, not page-level overflow.
- Continuity `--space-3` / `--space-5` documented as Phase 5 disposition — **do not invent** additional non-grid values.

## Typography

Reuse the locked type scale. Phase 13 markup declares **exactly 4 sizes** and **exactly 2 weights** (400 + 600). No fifth size (do **not** use `text-xl` as a separate contract size).

| Role | Token / utility | Size | Weight | Line Height | Used for |
|------|-----------------|------|--------|-------------|----------|
| Heading | `--text-h1` / `text-3xl` | clamp 2→3rem | 600 | 1.1 | Page H1 unchanged this phase |
| Subhead | `--text-h2` / `text-2xl` | clamp 1.5→2rem | 600 | 1.2 | Modal titles «Превью материала», «Превью письма»; **email subject** inside modal (`font-display` + Subhead size — maps former `text-xl` into this role) |
| Body | `--text-body` / `text-base` | **1.0625rem (17px) only** | 400 | 1.5 | Markdown body, email iframe content (backend HTML), empty-body copy, material item title under modal H2 (title may use weight 600) |
| Label | `--text-overline` / `text-xs` | 0.75rem (12px) | 600 | 1.4 | Provenance label; connecting-text hint; email modal caption; counts row (counts may use Label size at weight 400 for quieter meta) |

**Size count for Phase 13 markup:** Heading · Subhead · Body · Label = **4**. No other size tokens in new markup.

Weights: **400 regular** + **600 semibold** only in new Phase 13 markup.
Exception: existing `font-medium` (500) on shared controls — reuse only; do not expand.

Material modal title (item title under modal H2): Body size, weight 600, wrap with `break-words`.
Email subject inside modal: **Subhead** role (`font-display` + Subhead size/`text-2xl` or `--text-h2`, weight 600) — **not** a separate `text-xl` size.

## Page & Component Contracts

### Material preview modal — ADUX-01 (D-01…D-06)
- Data from enriched shortlist item only — **no fetch-on-open**.
- Body: `react-markdown` + `remark-gfm` + `rehype-sanitize` + `rehype-slug` (mirror `MaterialPage.jsx`).
- Scrollable panel; close `✕` + `aria-label="Закрыть"`; return focus to row trigger.
- Reader link complements body — never replaces it.
- Missing dek: keep Phase 5 honest fallback **«Краткое описание недоступно.»** only if dek remains shown; CONTEXT order prioritizes provenance/counts/body — dek may stay under title as secondary meta if already present; do not invent dek.

### Email preview modal — ADUX-02 (D-07…D-12)
- Backend owns HTML; FE must not assemble email markup.
- iframe: empty `sandbox` (no scripts/forms); `srcDoc={html}`; `data-testid="email-preview-frame"`.
- Loading / error states unchanged from Phase 5 except retry label **«Повторить превью»**.
- Subject line remains above iframe — **Subhead** typography role (see Typography).
- Email HTML must not include issue URL (issue created at send) (D-11).

### Interstitial / intro — ADUX-03 (D-13…D-16)
- Hint under connecting-text textarea: **«Пустая строка = новый абзац»** (`text-xs text-muted` — Label size).
- No markdown toolbar this phase.
- Visual paragraph honesty is proven in email iframe after preview (backend `render_interstitial_html`), not via live textarea preview.

### test-header — ADUX-04 (D-17…D-20)
- **No** UI filter, badge, or scrub control.
- Preview surfaces must not display ban-list tokens after data cleanup; enforced by asserts + migration, not render-time stripping.

### Out of scope UI
- Draft→ready control (ADUX-05) — Phase 14
- «Обоснование» / score_factors honesty (ADUX-06) — Phase 14
- PIPE config UI, live SMTP, markdown live-preview toolbar
