## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline internals → sink | Mapped error reason/stage and DTO fields cross into the formatter on the failure path |
| config loader → stderr | `ConfigurationError`/`TemplateLoadError` text crosses into the config debug line |
| CLI → stdout/JSON consumers | The error envelope and exit code that debug must never alter |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-04 | Information Disclosure | metadata + failure debug lines | high | mitigate | Metadata line emits `video_id` only (D-06); failure line emits `reason`/`exit_code` only, never `message`/`context`/bodies; tests assert the author, `source_url`, and message/body text are absent. |
| T-15-05 | Tampering | `stage_failed`/`config_error` emission | medium | mitigate | Emission is guarded and non-raising; redaction masks instead of aborting; tests assert the exit code and JSON envelope are unchanged versus the flag-off path. |
| T-15-06 | Information Disclosure | `stage=config` debug line | medium | mitigate | `config_error` runs `sanitize` (registry + denylist) on the assembled line; with no settings the regex-only net still covers cookies/tokens/JWT/userinfo. |
| T-15-SC | Tampering | npm/pip/cargo installs | high | mitigate | No packages are installed this phase (stdlib + existing deps only); if any package is added, run the package-legitimacy gate and block on a human checkpoint for `[ASSUMED]`/`[SUS]`. |
