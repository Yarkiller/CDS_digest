# Phase 18 Plan 01 — Tracer: an admin reads a draft end-to-end through the new preview endpoint (ADUX-07, ADUX-08)

<objective>
Lead the phase with one production-quality end-to-end slice through every backend layer this phase touches: `MaterialRepository.get_by_slug` → a NEW draft-only use case `get_material_for_preview` → a NEW `GET /admin/materials/{slug}` route behind the existing `require_admin` DB-role gate → the HTTP boundary → `TestClient`, returning the reader DTO verbatim. Nothing on `/materials/{slug}` or `get_material_for_reader` changes, and no new port, adapter or composition wiring appears.

Purpose: backlog 999.1's defect is that the admin shortlist's «Открыть материал →» link points at a ready-only reader route, so it 404s exactly on the draft rows the admin is triaging. The honest fix is an additive admin-gated read surface that renders the *same* reader payload (D-01, D-02), keeping "draft ≡ missing" true on the public route (ROADMAP criterion 2). This plan builds that surface on the backend; `18-02` renders it in the SPA and `18-03` repoints the links.

Output: `backend/src/backend/application/use_cases/get_material_for_preview.py` (new), the `GET /admin/materials/{slug}` route + `_to_preview_response` in `backend/src/backend/interface/http/routes/admin.py`, `tests/unit/test_get_material_for_preview.py` (new), 8 added cases in `tests/unit/test_http_admin.py`, and one added reader-route case in `tests/unit/test_http_materials.py`.

**Reversibility note (no `checkpoint:decision` inserted, deliberately):** D-02 is rated `costly` — reusing `MaterialReaderResponse` as the preview payload means a later switch to a distinct preview DTO would change this endpoint's response contract and every consumer of it. `planner-reversibility.md` also names "gating a decision already made" as the anti-pattern, and D-02 was settled by the user in `18-CONTEXT.md`. The rating is therefore recorded on the implementing task (see `<reversibility>`) and flagged, not gated. Every other decision in this plan is `reversible`.

**Scope note:** the tracer task carries two files (the new use case + the route) because this project forbids production code before a failing test (`tdd.mdc`, `AGENTS.md`), so the RED HTTP test, the use case and the route are one indivisible vertical slice. There is no intermediate state in which the route exists without the use case.
</objective>
