# Phase 18 Plan 02 — Tracer: an admin reads a draft in the SPA's normal reader rendering (ADUX-07, ADUX-08)

<objective>
Lead this plan with one production-quality end-to-end slice through every frontend layer the phase touches: the new `admin/materials/:id` route in `App.jsx` → the reused `MaterialPage` (additive `preview`/`loadMaterial` props + the D-06 banner) → the new `fetchMaterialPreview` in `services/adminApi.js` → the `GET /admin/materials/{slug}` endpoint shipped by `18-01`, with the mock branch so the slice is reproducible under `VITE_USE_MOCKS=true`.

Purpose: ROADMAP criterion 1 requires the admin to read a draft in the *normal reader rendering*, and D-02 makes that structural — the same page component and the same markdown pipeline, not a second preview component that imitates them. The banner (D-06) is the only thing that distinguishes the surface, and it belongs to the route, never to the payload: `MaterialReaderResponse` carries no `status` field, so any `material.status` check in the component would be dead code (`18-RESEARCH.md` § Pitfall 5).

Output: the `admin/materials/:id` route, `MaterialPage`'s preview/redirect/forbidden behaviour and banner, `fetchMaterialPreview` with its mock branch, and the new Playwright specs in `tests/admin.spec.js`.

**Reversibility note (no `checkpoint:decision` inserted, deliberately):** reusing `MaterialPage` rather than forking a preview component carries D-02's `costly` rating (undoing it means rewriting the render path). `planner-reversibility.md` names "gating a decision already made" as the anti-pattern and D-02 was settled by the user in `18-CONTEXT.md`, so the rating is recorded on the task that implements it (`<reversibility>`) and flagged, not gated. D-06, D-12 and D-03 are all `reversible`.
</objective>
