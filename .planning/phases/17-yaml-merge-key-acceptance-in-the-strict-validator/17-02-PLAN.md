# Phase 17 Plan 02 — Teach the anchor-holder mistake (PIPE-04, PIPE-05)

<objective>
Complete the second half of the merge-idiom contract: give the most likely post-fix admin mistake an honest, teachable error. Under D-01 the fix is confined to the parse path and the locked four-key `extra="forbid"` schema is not widened, so the natural "reuse an anchor" spelling (`defaults: &base` + `<<: *base`) stays rejected — but today it is rejected twice over, first with the cryptic loader failure and then with Pydantic's English `Extra inputs are not permitted`. D-07 replaces that second message, for merge anchor holders only, with a Russian message that names the offending key and shows the correct form.

Purpose: the phase exists to remove exactly this class of cryptic error; leaving the anchor-holder case in English would reintroduce it for the most likely mistake any admin makes after the merge fix ships. The change is message-only — no new response shape, no schema widening, no UI hint (D-08).

Output: `_EXTRA_ANCHOR_KEY_MESSAGE` and `_anchor_holder_keys()` in the adapter, the anchor-gated translation inside the existing `ValidationError` comprehension, and the RED tests in `tests/unit/test_pipeline_config_merge.py` plus the HTTP envelope proof in `tests/unit/test_http_pipeline_config.py`.
</objective>
