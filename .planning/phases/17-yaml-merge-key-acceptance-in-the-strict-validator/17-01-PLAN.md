# Phase 17 Plan 01 — Tracer: valid merge document accepted end-to-end, merge bomb refused (PIPE-04, PIPE-05)

<objective>
Lead the phase with one production-quality end-to-end slice through the only layer this phase touches: a YAML merge-key (`<<`) document is accepted by the strict validator and persisted, and a merge bomb is refused with the structured 400 — all wired through `_StrictSafeLoader` → `YamlPipelineConfigValidator.validate()` → the existing HTTP `{errors:[…]}` envelope → the repository, with no HTTP-layer, composition, or schema change.

Purpose: the pre-fix failure is reproduced on this checkout — `_StrictSafeLoader.construct_mapping` constructs every key node *before* `SafeConstructor.flatten_mapping` can run, and the merge key node carries a tag PyYAML registers no constructor for, so a valid `<<` document dies with `could not determine a constructor for the tag 'tag:yaml.org,2002:merge'`. Making merges work makes `flatten_mapping` reachable, and `flatten_mapping` multiplies the node list (`k^depth`): a ~480-char document costs ~1.5 s and a ~515-char one ~4.3 s today, both far inside the 20 000-char cap. ROADMAP Phase 17 criterion 4 therefore requires the merge fix and the bound to ship **in the same diff** — there is no intermediate state where merges validate but expansion is unbounded. That is exactly why the parse-gate change is one task, not two.

Output: the parse-gate fix (merge-tag skip + pristine own-key snapshot), the merge-expansion bound (`_project` + `_MergeExpansionTooLarge` + `_MERGE_TOO_BIG_MESSAGE`), the RED oracle corpus in a new `tests/unit/test_pipeline_config_merge.py`, and the HTTP round-trip / zero-write proofs in `tests/unit/test_http_pipeline_config.py`.

**Reversibility note (D-01, D-02, D-04 — no checkpoint inserted, deliberately):** CONTEXT.md rates D-01 `one-way`, D-02 `costly`, and D-04 `costly`. `planner-reversibility.md` also states the anti-pattern is "gating a decision already made": D-01 was chosen by the user in `17-CONTEXT.md` and is a *constraint* on this task ("только фикс парсинга, схема нетронута"), not an open choice. The rating is therefore recorded on the task (see `<reversibility>`) and **no `checkpoint:decision` is inserted** — there is nothing left to ask. D-02 and D-04 are `costly`-only, which flags but does not block.

**Scope note:** the tracer task carries two files (the adapter and the new test module) and the whole parse-gate diff. There is no way to split it further without creating the ROADMAP-forbidden intermediate state, and no way to shrink it below two files because this project forbids production code before a failing test (`tdd.mdc`, `AGENTS.md`).
</objective>
