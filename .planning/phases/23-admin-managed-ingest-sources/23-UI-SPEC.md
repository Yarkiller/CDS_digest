| Pipeline page hint (kept) | **«Просмотр и правка без запуска пайплайна»** — unchanged under AdminLayout (Phase 22) |

**Banned anywhere in the sources section (and page tripwire D-22):** «Запустить», «Выполнить», «Запуск», «Планировщик», «Расписание».

**Interaction rules:**
1. **List (SRC-01):** on admin ready, GET sources; render rows or empty state; never hide the add form.
2. **Add (SRC-01 / SRC-02):** POST with kind + source_id + optional label; on 201 append/refetch from server; clear the form (clears `sourceFormDirty`); on 400 render structured errors and keep typed values.
3. **Toggle / delete (SRC-01):** immediate PATCH/DELETE; disable that row's controls while in flight; on failure keep prior server state + inline error (D-05).
4. **Guard (ADUX-10):** typing in id or label arms the Phase 19 dialog on SPA leave; kind-only change does not; successful add that clears the form disarms source dirty when YAML is clean.
5. **No second Save** for sources; YAML **«Сохранить конфиг»** remains the only Save on the page.

## Page & Component Contracts

### Host page & placement (D-02, Phase 22 host)
- Route `/admin/pipeline` unchanged; still nested under `AdminLayout` tabs «Дайджест \| Пайплайн».
- `AdminPipelineConfigPage.jsx` gains the sources section **above** the YAML empty/editor/toolbar stack.
- Suggested structure (top → bottom inside the ready branch): page hint → **IngestSourcesSection** → existing YAML blocks.
- `data-testid` recommendations: `ingest-sources-section`, `ingest-sources-heading`, `ingest-sources-empty`, `ingest-sources-zero-enabled`, `ingest-sources-list`, `ingest-source-row`, `ingest-sources-add`, `ingest-sources-id`, `ingest-sources-label`, `ingest-sources-kind`, `ingest-sources-id-help`, `ingest-sources-errors`, `ingest-sources-load-retry`.

### Service boundary (SRC-03)
- Only `web/src/services/ingestSourcesApi.js` talks to `/admin/ingest-sources` (mock + live + arm/reset harness mirroring `pipelineConfigApi.js`).
- No Supabase / SQL / storage SDK in components.

### Add form (D-04, D-06, D-07, D-13)
- Controls: kind `<select>` or equivalent segmented control (**«Канал»** / **«Плейлист»**), id text input, optional label input, primary **«Добавить источник»**.
- Default kind: **«Канал»** (`channel`).
- Short hint always visible under id; disclosure **«Где взять id?»** is a native `<details>` / button+region — both recipes inside.
- Client may disable Add when id is blank; **must not** claim client-side canonical validation as authority — server 400 is the teaching reject (SRC-02).
- `maxLength={120}` on label is allowed as UX; server still enforces max 120.

### Source list & rows (D-05, D-08, D-09, D-10)
- Each row: mono `source_id`; kind label; status; **«Включить»**/**«Выключить»**; **«Удалить»**; **«Открыть на YouTube»**.
- If `label` is non-null, show it as secondary Body/Label text near the id — display only (no edit).
- External URL built only from stored validated `source_id` + fixed path prefixes (D-08 / RESEARCH security note).
- Delete: confirm via `window.confirm` copy above, then DELETE; 204 → remove row from list.
- Toggle failure: control returns to prior checked/enabled visual; show inline error on that row.

### Empty & zero-enabled (D-11, D-12)
- Zero rows: empty heading; **no** zero-enabled hint.
- ≥1 row and all disabled: show zero-enabled hint above the list; list still rendered.
- Add form visible in both cases.

### Errors (SRC-02)
- Add 400: top-level `{ errors: [{ path, message }] }` — same rendering contract as Phase 16 pipeline errors **without** `line`.
- Duplicate message verbatim: **«Этот источник уже добавлен»**.
- List/load failure: retry control; do not blank the page shell.

### Unsaved-changes guard (ADUX-10, D-03, D-04)
- Widen only: `const yamlDirty = yaml !== savedYaml`; `const sourceFormDirty = …`; `const dirty = yamlDirty || sourceFormDirty`.
- Single `useUnsavedChangesGuard(dirty)` and single `UnsavedChangesDialog`.
- Kind-only change must **not** arm the guard.
- Tab leave to «Дайджест» and shell nav continue to fire the same dialog (Phase 22 — no carve-out).

### Out of scope UI (hard boundary)
- «Сохранить источники», buffered list diff, optimistic toggles.
- Inline label edit, soft delete, restore, per-source stats, last-ingest metadata.
- Run / schedule / «Запустить» / Atom-feed listing (Phase 24 / ING-*).
- `@handle` / URL → id helpers.
- shadcn / new component library.
- Redesign of AdminLayout tabs or YAML editor toolbar.
