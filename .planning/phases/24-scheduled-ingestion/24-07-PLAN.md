# Phase 24 Plan 07 — Gap closure G-24-3: the oneshot start-phase bound

<objective>
Replace the inert `RuntimeMaxSec=1800` with `TimeoutStartSec=1800` in `deploy/systemd/digest-ingest.service`, invert the text contract so the broken token can never return, correct every doc that asserts the inert mechanism, and prove on a real systemd host that a `Type=oneshot` run longer than the limit is killed without stamping `last_run_at`.

Purpose: Live UAT (test 3) proved that systemd 255 ignores `RuntimeMaxSec=` for `Type=oneshot`, so D-23 and threat T-24-32 were unimplemented: a hung `ingest-collect` held `/run/digest-ingest/lock` forever and every later tick exited 75, which `SuccessExitStatus=0 75` treated as success — a silent stop with no alert. The binding property is behavioural, not lexical: a hung run must be bounded, `last_run_at` must not be stamped, and the next tick must be due from the same cursor. `TimeoutStartSec=` is chosen because the whole useful life of a oneshot is its start phase (G-24-3).

Output: one edited unit line plus its comment, two inverted/extended checks in `tests/unit/test_phase24_systemd_units.py`, a runbook §4k/§5e correction with a reproducible live recipe, and corrected SECURITY/VERIFICATION records.
</objective>
