## Офсет под шапку (NAV-01)

Исходный факт, предъявленный при обсуждении: `<header>` липкий, но не постоянной высоты — `<nav className="… order-last w-full sm:order-none sm:w-auto">` переносится ниже `sm`, а `--header-height: 64px` (`web/src/index.css:117`) сегодня нигде не используется.

### Вопрос 1 — механизм

| Option | Description | Selected |
|--------|-------------|----------|
| Переменная `--header-height` + медиа-запрос (64px / ~112px) | Офсет = `calc(var(--header-height) + воздух)`; значение переопределяется на том же breakpoint, где шапка переносит nav (`sm`). Один механизм, оба вьюпорта, значение в одном месте | ✓ |
| Одно фиксированное значение для всех вьюпортов | Проще всего, но на мобильном шапка выше 64px — критерий «заголовок ниже шапки» провалится | |
| Измерять высоту шапки в JS и писать в CSS-переменную | Точно для любой ширины, но добавляет JS и риск мигания при первом скролле | |

**User's choice:** Переменная `--header-height` + медиа-запрос.
**Notes:** JS-измерение отклонено как лишний рантайм; фиксированное значение отклонено как заведомо ломающееся на телефоне.

### Вопрос 2 — воздух

| Option | Description | Selected |
|--------|-------------|----------|
| 16px (1rem) | Заголовок останавливается в 80px от верха; ощутимая пауза, не выглядит как ошибка скролла | ✓ |
| 8px (0.5rem) | Плотнее, больше текста во вьюпорте | |
| 24px (1.5rem) | Воздушнее, но может конфликтовать с липкой TOC (`top-24` = 96px) | |

**User's choice:** 16px (1rem).

## Охват якорей (NAV-01)

Предъявленный факт: «Содержание» с `href="#id"` существует дважды — `MaterialPage.jsx:28-57` и `RazborPage.jsx:38`, обе на `extractMarkdownHeadings`; других внутристраничных якорей в `web/src` нет.

| Option | Description | Selected |
|--------|-------------|----------|
| Глобально на `html` (`scroll-padding-top`) | Один механизм на весь продукт; покрывает материалы и разборы; ни один компонент не меняется | ✓ |
| Явно в двух правилах (`prose-column` материала + проза разбора) | Явнее по месту, но два места правки и третье появится с новой страницей | |
| Только материалы (`material-prose`) | Минимальный диф, но баг остаётся в разборах — задача закрыта формально | |

**User's choice:** Глобально на `html`.

## Контракт происхождения (NAV-02)

Пользователь изначально выбрал для обсуждения только офсет и охват; NAV-02 была предложена отдельно (половина фазы оставалась без решений) и выбрана к обсуждению.

Предъявленные факты: `/materials/:slug` линкуется из `IssueToc.jsx:10`, `MaterialListRow.jsx:14`, `MaterialPage.jsx:261`; `/issues/:number` линкуется только из `ArchivePage.jsx:71`; `IssuePage` уже получает `isCurrent` (`App.jsx:49`).

### Вопрос 1 — форма состояния

| Option | Description | Selected |
|--------|-------------|----------|
| `{ section: 'archive' \| 'base' }` — маркер раздела | Произвольный путь в состояние попасть не может, значит «вывести раздел из URL» структурно невозможно | ✓ |
| `{ from: '/archive' }` — путь происхождения | Гибко, но путь в состоянии — второй способ вывести раздел из URL, запрещённый ROADMAP | |
| `{ section: 'archive', issue: 12 }` — маркер + контекст | Даёт контекст сверх подсветки, но это новый навигационный элемент — новый скоуп | |

**User's choice:** `{ section: 'archive' | 'base' }`.

### Вопрос 2 — поведение после F5

| Option | Description | Selected |
|--------|-------------|----------|
| Подсветка сохраняется | `history.state` переживает F5, и это честно: читатель действительно пришёл из архива | ✓ |
| Гасить после перезагрузки | Требует сброса состояния на mount; строгое, но контринтуитивное чтение критерия 5 | |

**User's choice:** Подсветка сохраняется; «прямой заход» в тестах = свежий контекст.

### Вопрос 3 — материал из текущего выпуска

| Option | Description | Selected |
|--------|-------------|----------|
| Да — симметрия, «Выпуск» тоже подсвечивается | `IssueToc` получает проп раздела и пробрасывает `'issue'` / `'archive'` | |
| Нет — только «Архив» и «База», как буквально в требовании | Меньше правок, но асимметрия: из архива подсветка есть, из текущего выпуска — нет | ✓ |

**User's choice:** Только «Архив» и «База».
**Notes:** При этом архивная ветка всё равно требует проброса через `IssueToc` (критерий 3 ROADMAP), поэтому `IssueToc` правится как транслятор маркера — источником служит `isCurrent === false`, а не полученное состояние.

## Claude's Discretion

- Точное значение мобильной `--header-height` (измерить фактическую двухстрочную высоту; ориентир ≈112px — оценка, не факт).
- Форма медиа-объявления (отдельный `@media`-блок рядом с `--header-height`).
- API проброса: проп `section` у `IssueToc` / `MaterialListRow` либо обёртка в вызывающей странице; `'base'` не должен быть захардкожен внутри переиспользуемого `MaterialListRow`.
- Где валидируется маркер (`AppShell`, закрытый список двух значений; невалидное = ничего не зажжено).
- Тестовые фикстуры: критерий «длинная секция» невыполним на моке `rag-systems` (два заголовка), нужна расширенная или новая фикстура.

## Deferred Ideas

- Подсветка «Выпуска» на материалах текущего номера (отклонена в этой фазе, D-09).
- Ссылка «← Назад в архив» / «← Назад в результаты» — новый навигационный элемент.
- Сокращение мобильной шапки до одной строки — редизайн хрома, а не починка якоря.
- Сохранение раздела между сессиями через `localStorage` — прямо запрещено ROADMAP.
- Scroll-spy в «Содержании» (подсветка текущей секции при прокрутке) — не запрашивалось.
