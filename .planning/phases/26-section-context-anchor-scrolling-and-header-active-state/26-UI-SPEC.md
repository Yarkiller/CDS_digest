# Phase 26 — UI Design Contract

> Визуальный и поведенческий контракт для фронтенд-фазы. Сгенерирован gsd-ui-researcher, проверяется gsd-ui-checker.

Источники: `26-CONTEXT.md` (D-01…D-11 — locked), `.planning/ROADMAP.md` § Phase 26 (критерии 1-5), `.planning/REQUIREMENTS.md` (NAV-01, NAV-02), живой код `web/src`.

Фаза — **починка двух дефектов, а не новый UI**: ни одной новой строки копирайта, ни одного нового токена, ни одной новой раскладки. Всё, что контракт объявляет сверх существующего, — это два числовых значения (`scroll-padding-top`, мобильная `--header-height`), один атрибут (`aria-current`) и три литерала маркера (`'archive' | 'base' | 'issue'`).

> **Рев. 2 (2026-10-22).** Исправлены только формы rect-ассертов и учёт констант: добавлен гейт достижимости C-00, полоса `gap ∈ [1, 32]` оставлена только там, где документ даёт запас прокрутки; C-02 переписан на удлинённую фикстуру, C-02b добавлен как пин на короткой странице, C-04/C-05 переведены на три независимые претензии без верхней границы, C-06 требует удлинения разбора, мобильная константа исправлена на измеренные `196.6 / 122.6 → 200px`. Заблокированные решения D-01…D-11 не менялись.

## Spacing Scale

Объявленные значения кратны 4 (существующие токены `--space-*` в `web/src/index.css:95-105`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Зазоры строчных глифов (существующее) |
| sm | 8px | Компактные отступы внутри пилюль (существующее) |
| md | 16px | **Воздух офсета якоря — единственное новое значение фазы (D-03)** |
| lg | 24px | Вертикальный ритм секций (существующее) |
| xl | 32px | Разрывы мажорных блоков (существующее) |
| 2xl | 48px | Высота поля поиска `min-h-12` (существующее) |
| 3xl | 64px | `--header-height` на `sm+` (D-02) |

Exceptions (все — существующие или производные значения, не шаг шкалы; менять их в этой фазе запрещено):

- `--header-height`: хром-размер, а не шаг шкалы. `64px` на `≥640px` (locked, D-02); ниже `640px` — переопределение, **измеренное в браузере** и округлённое вверх до кратного 4. Измерено на mock-сборке: `document.querySelector('header').getBoundingClientRect().height` = **196.6px на 390×844** и **122.6px на 639×844**; максимум `196.6` → вверх до кратного 4 = **`200px`** (D-C1). Число `200px` — контракт для ширины `<640px`; фигура `≈112px` из рев. 1 была оценкой и **устарела**: использовать её нельзя, иначе C-04/C-05 не сойдутся.
- `px-2.5` (10px) — горизонтальный паддинг пилла шапки (`linkClass`, `AppShell.jsx:13`). Не шаг шкалы и **не нормализуется** в 8/12px: C-18 требует, чтобы `px-2.5` присутствовал в активном и неактивном состоянии буквально. «Приведение к шкале» сломает пин.
- `80px` — производный офсет `calc(64px + 16px)` (D-02/D-03). Кратен 4, но в таблице токенов отсутствует, потому что это вычисление, а не токен. Не заменять литералом и не заводить под него новый `--space-*`.
- `top-24` (96px) у липкой колонки «Содержание» (`MaterialPage`, `RazborPage`). Остаётся 96px даже при офсете 80px: пересчёт этого отступа сдвинул бы рейл, а это редизайн.
- Зазор офсета проверяется по живым прямоугольникам, поэтому расхождение между `--header-height` (64px) и фактической высотой шапки (измерено `72.6px` на 1280×800: `min-h-12` поиска 48 + `py-3` 24 + `border-b` 1) не «чинится» правкой токена — D-02 фиксирует 64px. Ожидаемый остаточный зазор на десктопе ≈`7.4px` (`80 − 72.6`), а не 16px; это принятый результат, а не дефект, и именно он объясняет границы полосы: снизу `1px` (не пинить пиксель), сверху `32px` (запас на состав шапки).

## Typography

Фаза **не вводит ни одного нового размера и начертания**. Объявлены роли, которые реально рендерятся в затронутых поверхностях (значения — то, что уже дают утилиты Tailwind v4):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Проза статьи/разбора (`prose-column`, `leading-relaxed`) | 16px | 400 | 1.625 |
| Подпись пилюли шапки и ссылки «Содержания» (`text-sm`) | 14px | 400 | 1.43 |
| Заголовок-цель якоря `h2` (`text-2xl font-semibold`) | 24px | 600 | 1.33 |
| Подзаголовок `h3` (`text-xl font-semibold`) | 20px | 600 | 1.40 |

Итого: **4 объявленных размера** (14 / 16 / 20 / 24) и ровно 2 начертания (400, 600).

Таблица — **подмножество живой шкалы, а не её исчерпывающий перечень**: в тех же поверхностях уже рендерятся 30px (`[&_h1]:text-3xl` в `prose-column`, `MaterialPage.jsx:231`), 36px и 48px (`text-4xl sm:text-5xl` заголовка страницы, `MaterialPage.jsx:205`). Эти три значения фаза **не меняет** и новых не вводит; лимит «≤4 объявленных» выполняется ограничением, а не умолчанием — любое изменение кеглей вне таблицы обязано быть отдельным решением с собственной причиной.

Заголовок-цель не получает ни `font-bold`, ни нового кегля: смена начертания при активном состоянии запрещена (см. C-18).

**Фокусная точка (Dimension 2 — Visuals).** Единственная акцентная поверхность экрана — залитый пилл активного раздела в шапке; он и есть focal point фазы. Второй акцентный объект не появляется: заголовок-цель якоря, `:target`-подсветка, подчёркивание активной ссылки «Содержания», рамка и любые новые маркеры акцентом **не** красятся. Два акцентных пятна на одном экране = нарушение контракта.

Запрещено в этой фазе: акцентный цвет у заголовка-цели, у `:target`, у подчёркивания якоря, у рамки активного раздела, у любых новых маркеров. Не-цветовой сигнал активного раздела — атрибут `aria-current` (D-11). Иконки, подчёркивания и точки-индикаторы не добавляются: смена визуального языка навигации вне скоупа.

## Interaction Contract

Каждый пункт ниже — контракт, который обязан существовать в RED-виде до production-правки (`.cursor/rules/tdd.mdc`). «RED сегодня» = почему ассерт падает до фикса, и это обязана быть **истинная** причина (отсутствие офсета / отсутствие атрибута), а не недостижимость фикстуры; «pin» = сегодня зелёный, но обязан остаться зелёным (характеризационный пин, защищает от регрессии).

### C-00. Гейт достижимости — предусловие каждого rect-ассерта

Формулировка «заголовок встал в полосу `[1, 32]`» проверяема только там, где документу хватает запаса прокрутки: браузер ставит цель в `scroll-padding-top` лишь если `maxScroll` это позволяет. На существующих фикстурах запаса нет, поэтому **каждый** rect-ассерт (C-02…C-06) начинается с гейта, измеряемого до клика:

```js
const gate = await page.evaluate((anchorId) => {
  const doc = document.documentElement
  const header = document.querySelector('header').getBoundingClientRect()
  const pad = Number.parseFloat(getComputedStyle(doc).scrollPaddingTop) || 0 // 'auto' → 0
  const target = document.getElementById(anchorId) // id из href ссылки «Содержания»
  const headingDocTop = target.getBoundingClientRect().top + window.scrollY
  const maxScroll = doc.scrollHeight - window.innerHeight
  return { headerHeight: header.height, headerBottom: header.bottom, pad, headingDocTop, maxScroll }
}, anchorId)
// строгая форма: цель достижима, даже если офсет увеличится
gate.reachable = gate.maxScroll >= gate.headingDocTop
```

Правила:

1. **Полоса — только там, где пункт её объявляет, и только при достижимости.** `gap ∈ [1, 32]` объявляют ровно три пункта: C-02, C-03, C-06; каждый обязан получить `reachable === true`. C-04 и C-05 полосу **не** объявляют: одно мобильное значение `200px` даёт остаточный зазор ≈19.4px на 390 и ≈93.4px на 639, поэтому у них свои три претензии (см. ниже).
2. **Недостижимая цель не проверяет полосу.** `reachable === false` → полоса **не проверяется вообще** (иначе ассерт RED навсегда и остаётся красным даже после корректного фикса); проверяется только `heading.top >= header.bottom + 1 && heading.bottom <= innerHeight`, а RED пункта обязан приходить из отдельного ассерта, названного в самом пункте. Единственный пункт, который по построению живёт в этой форме, — C-02b.
3. **Вакуумность запрещена.** C-02, C-03, C-06 требуют `reachable === true` как жёсткое предусловие с сообщением: «фикстура: maxScroll=X < headingDocTop=Y — удлинить тело (тестовая правка)». Молча зеленеть при недостижимой цели нельзя.
4. **Гейт строже минимальной формулы.** Требуется `maxScroll >= headingDocTop`, а не `headingDocTop − pad`: это гарантирует достижимость при любом будущем значении офсета и убирает пограничную зону, где RED падал бы из-за фикстуры, а не из-за отсутствия офсета. Условие эквивалентно «под целью ≥ одного вьюпорта тела»; фикстуры C-02/C-03/C-06 берут запас 1.25 вьюпорта, чтобы гейт не проходил «на грани».
5. **Гейт измеряется в состоянии «до фикса».** `headingDocTop` и `maxScroll` от офсета не зависят; `pad` читается как есть (`auto` → 0) и в гейте не используется.

Измерено на mock-сборке (2026-10-22), `reachable` — по строгой форме:

| Fixture | Viewport | `header.height` | `headingDocTop` | `maxScroll` | `reachable` |
|---|---|---|---|---|---|
| `/materials/rag-systems`, первый `h2` (`#user-content-введение`) | 1280×800 | 72.6 | 395.7 | 61 | **нет** (нужно 395.7) |
| `/materials/rag-systems`, первый `h2` | 390×844 | 196.6 | 710 | 436 | **нет** (нужно 710) |
| `/materials/rag-systems`, первый `h2` | 639×844 | 122.6 | не измерено | не измерено | решает гейт в самом тесте |
| `/razbory/3`, первый `h2` | 1280×800 | 72.6 | 478 | 193 | **нет** (нужно 478) |

Вывод для планировщика: **ни одна существующая фикстура не даёт запаса прокрутки**. Поэтому C-02, C-03 и C-06 требуют тестовой правки контента (`web/src/data/mock.js`, правка тестовая, production не трогается): под целью должно оставаться ≥ 1.25 вьюпорта тела.

### NAV-01 — офсет прокрутки

- **C-01. Один механизм, объявленный один раз.** В `web/src/index.css` появляется ровно одно правило `scroll-padding-top: calc(var(--header-height) + 1rem)` на `:root` (D-01/D-02). Запрещено: `scroll-mt-*` / `scroll-margin-top` на заголовках, `scroll-behavior: smooth` (новое визуальное поведение + недетерминизм ассерта), измерение высоты шапки в JS.
  - *Evidence:* `parseFloat(getComputedStyle(document.documentElement).scrollPaddingTop)` на `/materials/rag-systems` при 1280×800 лежит в `[header.height + 1, header.height + 32]` — то есть в `[73.6, 104.6]` при измеренных `72.6`; ожидаемое значение после фикса `80`.
  - *RED сегодня:* `scrollPaddingTop = auto` (parse → 0) → ассерт обязан падать числом, а не `NaN`; `Number.parseFloat(...) || 0` — часть контракта.
- **C-02. Короткая секция (критерий 1).** Фикстура: `/materials/rag-systems` после тестового удлинения `body_markdown` — **первая секция остаётся короткой** (её собственное тело < 1 экрана), но под целью ≥ 1.25 вьюпорта дальнейшего текста, иначе гейт C-00 не пройден. 1280×800: гейт C-00 → `reachable === true`, затем клик по первой ссылке `getByTestId('material-toc')` → `gap = heading.top − header.bottom ∈ [1, 32]` и `heading.bottom <= innerHeight`.
  - *Ожидание после фикса:* `gap = 80 − 72.6 ≈ 7.4` — полоса держится на остаточном зазоре (см. Spacing), поэтому и нужна верхняя граница 32.
  - *RED сегодня:* `scrollPaddingTop = auto` (parse → 0), цель достижима, поэтому браузер ставит заголовок в `top ≈ 0` → `gap ≈ −72.6 < 1`. Падает **именно** из-за отсутствия офсета, не из-за фикстуры.
- **C-02b. Короткая страница — пин без верхней границы.** Цель, до которой документ не даёт доскроллить: по умолчанию `/materials/empty-dek-article` (единственный `h2`, тело короче экрана); если `rag-systems` решено не удлинять, допустим он сам. Гейт C-00 обязан вернуть `reachable === false` — это проверяется явно, чтобы пин не стал вакуумным. Дополнительно фиксируется измеренный зазор **до** клика и после: он обязан быть `> 32` (иначе цель стоит слишком близко к верху, браузер дотягивает её почти под шапку, и пин падал бы не по той причине — тогда берётся другая короткая страница). Проверяется только `heading.top >= header.bottom + 1 && heading.bottom <= innerHeight`; полоса `[1, 32]` здесь **не** проверяется.
  - *pin:* сегодня зелёный (заголовок и так виден, документу некуда двигаться). Падает, если «починка» начнёт принудительно скроллить короткую страницу, добавит отступ, выталкивающий заголовок за фолд, или если полосу всё-таки впишут в недостижимую фикстуру.
- **C-03. Длинная секция (критерий 2).** Та же удлинённая фикстура: ≥6 заголовков и ≥3 экрана тела (точные числа фиксируются в тесте). Гейт C-00 → `reachable === true`. До клика явно проверить `heading.getBoundingClientRect().top > window.innerHeight` (иначе тест вакуумный — цель уже на экране), затем клик по глубокой ссылке → `gap ∈ [1, 32]` и заголовок во вьюпорте.
  - *RED сегодня:* цель под шапкой — браузер ставит заголовок в `top ≈ 0`, `gap ≈ −72.6`.
- **C-04. Телефон 390×844 (D-02, D-C1).** `details` «Содержание» раскрыт. Три независимые претензии, каждая со своим доказательством:
  1. `getComputedStyle(document.documentElement).getPropertyValue('--header-height').trim() !== '64px'` — сегодня `64px`.
  2. `parseFloat(getComputedStyle(document.documentElement).scrollPaddingTop) >= header.height + 1` — сегодня `auto` → 0 при `header.height = 196.6`.
  3. После клика по ссылке: `heading.top >= header.bottom + 1` **и** `heading.bottom <= innerHeight` — без верхней границы полосы.
  - *RED сегодня:* претензии 1 и 2 не выполнены → падение по ожидаемой причине. Претензия 3 — пин: цель на 390 недостижима (`maxScroll = 436 < docTop = 710`), зазор остаётся ≈77px и заголовок виден.
  - *Ожидание после фикса:* `scrollPaddingTop = 216` (`200 + 16`), `gap = 216 − 196.6 ≈ 19.4`. Полоса `[1, 32]` здесь **не требуется**; если планировщик захочет её добавить, он обязан сначала доказать достижимость гейтом C-00 (сегодня её нет) и записать это отдельным пунктом.
- **C-05. Граница breakpoint 639×844.** Те же три претензии, что C-04; на 639 навигация уже переносится, шапка высокая (`header.height = 122.6`). Ловит медиа-запрос с неверной границей (600px, `min-width` вместо `max-width`): тогда `--header-height` останется `64px` и претензия 1 упадёт.
  - *Форма претензии 3:* здесь она одна и та же — `heading.top >= header.bottom + 1 && heading.bottom <= innerHeight`; достижимость на 639 не замерялась, гейт C-00 решает в самом тесте, пин это или RED (если цель достижима, сегодня заголовок встанет в `top ≈ 0` и претензия падает).
  - *RED сегодня:* токен `64px`, `scroll-padding-top` отсутствует.
  - *Ожидание после фикса:* офсет `216` при `header.height = 122.6` → зазор ≈93.4px. Полоса `[1, 32]` на 639 **не проверяется и не должна**: одно мобильное значение (`200px`) физически не даёт 1…32px одновременно на 390 и на 639, а второе значение = настройка хрома под ширину, то есть редизайн вне скоупа. Проверяется «заголовок ниже шапки и во вьюпорте».
- **C-06. Разбор (D-05).** Длинный published-разбор (`/razbory/2` или `/razbory/3`) после тестового удлинения `body_markdown` в `web/src/data/mock.js`. **Новый разбор не добавляется**: `tests/razbory.spec.js:16` пинит `chronology-item` в количестве 4. Под целью ≥ 1.25 вьюпорта тела. Гейт C-00 → `reachable === true`, клик в `getByTestId('razbor-toc')` → `gap ∈ [1, 32]`, заголовок во вьюпорте. ## Copywriting Contract

Фаза **не добавляет ни одной пользовательской строки**. Единственные новые данные в DOM — атрибут `aria-current` и `state.section`; они не отображаются.

| Element | Copy |
|---------|------|
| Primary CTA | отсутствует — фаза не вводит действий |
| Empty state heading | не применимо — «пустое» состояние фазы это отсутствие подсветки, текста у него нет |
| Empty state body | не применимо |
| Error state | не применимо — новых состояний ошибки нет; `ServiceUnavailable` и «… не найден» не меняются |
| Destructive confirmation | отсутствует — деструктивных действий в фазе нет |

Инварианты копирайта (проверяемо существующими локаторами):

- Подписи пиллов остаются байт-идентичными: «Выпуск», «Архив», «База», «Голосование», «Разборы», «Админ» — `getByRole('link', { name: /^Архив$/ })` продолжает находить ровно один узел.
- «Содержание» остаётся подписью и `summary` дисклоуза, и заголовком рейла; `aria-label="Содержание"` на `<nav>` не меняется.
- Запрещено добавлять «вы здесь», хлебные крошки, «← Назад в архив», бейдж раздела, `title`/`aria-label`, объясняющий происхождение: это новые навигационные элементы, вынесенные в Deferred.
