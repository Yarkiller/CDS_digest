<objective>
Close the phase with the three behaviours that only become assertable once the trigger path exists end to end: history discipline (a submit replaces, it never stacks query variants), the error boundary (panel, retry, never cached, never in the header), and the XSS probe that proves `?q` is rendered as text everywhere it lands.

Purpose: the earlier plans each widened one boundary. This one proves the boundaries are sealed — that Back cannot re-enter a stale query variant, that a failure is never persisted into the snapshot cache, and that attacker-controlled text in `?q` cannot become markup.

Output: `{ replace: true }` on both submit paths — the header owns the one-shot `state.submitId` marker (27-03), the page form writes `?q` with **no** `state` and keeps calling `runSearch` (D-02 + D-05) — plus the C-21 role-chip URL write, the error-path assertions (including the sticky `__DIGEST_FAIL_NEXT_KNOWLEDGE__` reset), and the S11 injection probe plus its source gate.
</objective>
