<assumption_delta_decision>
noun: "search trigger" — the `?q` URL search parameter on `/knowledge`
decision: no-change
rationale: The two `pluralization` signals describe a removed duplicate click and a removed duplicate request. This plan makes the trigger the *only* executor (form submissions write the URL instead of calling the adapter path) and makes history replace rather than stack entries (fewer entries, not more). The trigger's cardinality stays one; no model, migration or pluralised entity is involved.
</assumption_delta_decision>

<deviations>
1. **`Back` destination is asserted as "not `/knowledge`", not as a specific URL.** After a `replace`, the previous entry is whatever the browser session had before the app's first navigation; asserting an exact destination would encode browser history details. The contract (C-07) is only that Back leaves `/knowledge`.
2. **The sticky `window.__DIGEST_FAIL_NEXT_KNOWLEDGE__` flag is deliberately not cleared before the "not cached" assertion.** It is the only way to prove a revisit *attempted* a request rather than restoring a snapshot without adding an instrument. `handleRetry` still clears it, which is what makes case (a) recoverable.
3. **No new user-facing string.** `«Не удалось найти материалы»` and `«Повторить»` are pre-existing `ErrorPanel`/page literals; the acceptance grep pins exactly one source hit for the title.
</deviations>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `?q` → DOM (field, live region, rows, hints) | The primary injection surface: attacker-controlled text rendered on `/knowledge` |
| `?q` → history state | Replaced entries must not accumulate attacker-chosen URLs in session history |
| sticky failure harness → retry | A test-controlled global that must not leak into production behaviour |
| `?q` → module cache | An error must not be cached, or a permanent failure would be replayed as empty results |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-15 | Tampering / XSS | `?q` in the field, live region, hint block, row titles | critical | mitigate | Text-node / controlled-`value` rendering only; S11's two payloads assert no element, no handler, no title change, no markup in the live region; the source gate forbids `dangerouslySetInnerHTML`, `innerHTML`, `document.write` and `document.title =`. |
| T-27-16 | Tampering (history poisoning) | `setSearchParams` / `navigate` | medium | mitigate | Both submit paths replace, so a crafted `?q` cannot accumulate as back-navigable entries; the chip path leaves the URL unchanged. |
| T-27-17 | Repudiation / availability | error path replaying a cached failure | medium | mitigate | `forgetSearchSnapshot` runs in the `catch`; the "not cached" case proves a revisit issues a new attempt (Δ=+1) even while the sticky flag is armed. |
