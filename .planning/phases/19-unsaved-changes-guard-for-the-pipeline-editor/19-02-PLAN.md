# Phase 19 Plan 02 — The unsaved-changes guard: in-app blocker + reload/close backstop (ADUX-09 criteria 1-3)

<objective>
Deliver the unsaved-changes guard for the admin pipeline editor on both paths ADUX-09 names, using two mechanisms because neither alone is sufficient: the React Router data-router `useBlocker` covers in-app SPA navigation (and cannot cover a hard reload), while a correct `beforeunload` handler covers reload/close/tab (and cannot show app copy). The dirty signal already exists and is correct — `const dirty = yaml !== savedYaml` — so the guard consumes it and never re-derives it.

Purpose: backlog 999.6 (`WR-04` + `WR-05`) recorded a shipped guard whose `beforeunload` handler called `window.confirm` (nondeterministic in real browsers) and whose in-app path was unguarded entirely, so a shell-nav click silently discarded the draft. This plan closes both halves and replaces the test that green-lit the broken handler.

**Two production-quality mechanisms, one `dirty` bit.** In-app: `useBlocker(dirty)` (boolean form — one predicate, no pathname carve-out, so the `RequireAuth` 401 -> `/login` redirect is blocked too, D-04) feeds `UnsavedChangesDialog`, which owns the Russian copy and the two actions (`blocker.proceed()` / `blocker.reset()`). Reload/close: a dirty-scoped effect registers `armBeforeUnload`, which does exactly `event.preventDefault()` and a truthy `event.returnValue` and nothing else (D-05).

**Reversibility note (no `checkpoint:decision` inserted, deliberately):** D-07 is rated `costly` — re-inlining the guard later means re-splitting the copy and behaviour across two editors and re-pinning both test surfaces. The rating is recorded on the packaging task; it is not gated because the user already deferred this choice to Claude in `19-CONTEXT.md` and the reasoning supports the reusable packaging (Phase 23's `ADUX-10` must reuse it).

**Scope boundary — D-11:** `ADUX-10` (the ingest-sources editor guard) is deliberately NOT delivered by this plan — it is owned by Phase 23. Phase 19's obligation is only that the guard be *extractable*: the util/hook/dialog trio carries one home for the leave copy and a boolean `dirty` parameter, so Phase 23 arms the same guard on a second editor without rewriting or forking it. Do NOT add an ingest-sources guard, an ingest-sources test, or any editor-generic abstraction beyond what the trio needs.

Output: `web/src/utils/unsavedChangesGuard.js`, `web/src/hooks/useUnsavedChangesGuard.js`, `web/src/components/UnsavedChangesDialog.jsx` (all new), the guard wired into `web/src/pages/AdminPipelineConfigPage.jsx`, the amended tripwire plus new journeys in `tests/admin.spec.js`, and a `node --test` unit gate in `tests/unit/test_unsaved_changes_guard.js`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser window (document unload) -> app | The browser fires `beforeunload`; page code cannot drive or decorate its prompt, so any app code in that handler is a liability |
| Router navigation -> app state | A navigation intent (shell link, `navigate()`, or the `RequireAuth` redirect) meets the dirty draft |
| App render -> DOM | The modal is a new DOM surface; only a constant string may be rendered into it |
| `window.addEventListener` registry | A leaked or duplicated `beforeunload` listener would trap the user on every unload |
