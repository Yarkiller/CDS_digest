# 25-09. Гейты, которые не умеют падать: альфа тинта из класса (GAP-25-6) и контракт статусов `G-16` (GAP-25-7)

## Objective

Закрыть два «вакуумных» гейта, доказанных мутациями в `25-REVIEW.md`:

### GAP-25-6 (WR-10) — `G-14` измеряет константу, а не класс

`tests/unit/test_semantic_token_coverage.js:113-117` пинит `alpha: 0.15 / 0.2 / 0.1` рядом с токенами, а классы в дереве живут отдельно. Проверено: `bg-success/15 → bg-success/60` оставляет `npm run test:js` **зелёным**, хотя реальный композит — 4.181 (`bg-app`), 4.094 (`paper-2`), 4.264 (`paper`) в светлой и 2.699…3.011 в тёмной, то есть порог 4.5 пробит во всех шести парах. Дополнительно `tests/admin-chrome.spec.js:379` держит **вторую копию** той же константы (`tintAlpha = { success: 0.15, voting: 0.2 }`), поэтому e2e меряет ту же выдуманную подложку.

**Гейт обязан читать альфу из класса.** План переписывает `G-14` так, чтобы сайты тинтов собирались из дерева, альфа парсилась из токена, а каждая измеренная пара называла файл-источник.

### GAP-25-7 (WR-08 / WR-09) — `G-16` R1 и R3 не срабатывают

- **R1** (`REGEX_ASSERTION`, строки 485-486) видит только `toMatch|toContainText|toHaveText|getByText`. Формы `filter({ hasText: /A|B/ })`, `getByRole("status", { name: /A|B/ })` и `toHaveAccessibleName(/A|B/)` проходят мимо — одна проверка снова может покрывать два исхода.
- **R3** (`toastReaders`, строки 555-570) требует подстроки `backgroundColor` / `borderTopColor` **где угодно в файле**. Обе подстроки уже есть в хелпере `styleTriple()` (`tests/admin-chrome.spec.js:153-154`), поэтому удаление всех цветовых `expect` у тоста оставляет гейт зелёным — ровно тот класс дефекта, который `G-15` закрывал.

**R2 работает и не трогается** (`Выпуск опубликован` / `Уже отправлено` читаются построчно через `literalIsAsserted`).

**Purpose.** Гейт, который не падает на своей же мутации, — это документация, а не защита: он разрешает следующей правке вернуть 3.5:1 подпись или 1.00:1 тост, оставаясь зелёным.

**Output.** Переписанный `G-14` (альфа из класса, провенанс, детектор неразобранных альф), четыре новых proof-теста, R1/R3 с окном и расширенными формами ассерта, вывод альфы из класса в e2e. Production-файлы **не меняются** — этот план правит только тесты, и это его главная ценность: он доказывает, что 25-08 и 25-06 держатся проверками, а не совпадением.

### Четыре ловушки, проверенные чтением

1. **Вариантный префикс.** `ErrorPanel.jsx:16` — это `hover:bg-danger/15`, а не `bg-danger/15`. Регексп сайта обязан допускать префикс варианта: `^(?:[\w-]+:)?bg-(success|voting|danger)\/(\d{1,3})$`. Без этого сайт невидим, а анти-вакуум всё равно зелёный (три других токена есть) — вакуумность вернулась бы тихо.
2. **`G-14` сейчас читает `--color-{tint}` через `light.get(...) ?? dark.get(...)`** (`:938`), потому что тинт темо-плоский по `G-3`. Это поведение сохраняется: переписывается только источник **альфы**, не источник цвета.
3. **`--color-danger-ink` в обеих темах разный** (`#F87171` / `#B91C1C`), поэтому proof на `/60` обязан брать `ink` из того же блока, что и подложку, — иначе числа «поедут» незаметно.
4. **`REGEX_ASSERTION` не снимает комментарии.** После расширения форм ассерта комментарий вида «`{ name: /A|B/ }`» попадёт в скан. Поэтому новый `REGEX_LITERAL` работает по источнику с вырезанными комментариями (тот же приём, что `G-0` использует для CSS: `replace(/\/\*[\s\S]*?\*\//g, '')` + `//`-строки).

### Замеренный probe (вход для анти-ложноположительного пина)

Замерено на текущем дереве: в `tests/*.spec.js` **13** регулярных литералов с ≥ 2 альтернативами (**10** уникальных тел) и **0** нарушителей под правилом «альтернатив ≥ 2 **и** тело целиком матчит ≥ 2 зарегистрированных `STATUS_LITERAL`». Ноль держит именно вторая половина правила: формы вроде `/(dark|light)/` и `toHaveURL(/$/)` имеют ≥ 2 или 1 альтернативу, но не покрывают ни одного (или ровно один) статус-литерал. Обе половины пинятся proof-тестом, а его точная граница (13/10/0) — вход этого плана.
