> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase is a repair, not a feature.** Every value below either (a) makes an already-written
> utility real, (b) replaces a theme-dependent label with a theme-independent one, or (c) reduces
> existing chrome. No route, field, panel or component is added.

## Typography

Exactly **4 sizes** and **3 weights** across the surfaces this phase touches — 12 / 14 / 16 / 24 px;
**400 regular + 500 medium + 600 semibold**. No fifth size and no fourth weight. Weight 500 is
**pre-existing and frozen**: the phase inherits it on unchanged class chains and adds none. The table
below is normative for in-scope elements; rule 4 then records the inherited 500 chains that this
contract explicitly does *not* restyle.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Heading | **24px** (`text-2xl`) | **600** active / **400** inactive | **1.33** (32px) | Section tabs «Дайджест｜Настройка»; both admin `h2` blocks (`IngestSourcesSection` :171, `IngestionScheduleSection` :140); the unsaved-changes dialog `h2`; the rejected-source error `h3` |
| Body | **16px** (`text-base`) | 400 | **1.5** (24px) | Ingest field values only — `ingest-sources-kind` select, `ingest-sources-id` / `ingest-sources-label` inputs (`IngestSourcesSection.jsx:270`, `:286`, `:299`) — plus the YAML editor, the empty-state headline («Пока нет источников») and reader prose. **The schedule time input is not in this row** (see exception 6). |
| Label | **14px** (`text-sm`) | **500 for filled CTA labels; 400 for row actions, secondary/outline actions and `<option>` text** | **1.43** (20px) | 500: `Добавить источник` (`IngestSourcesSection.jsx:308`), `Уйти без сохранения` (`UnsavedChangesDialog.jsx:53`), `ActionButton.jsx:29` base primitive. 400: row actions `Включить`/`Выключить`/`Удалить`/`Открыть на YouTube` (`IngestSourcesSection.jsx:229`, `:232`, `:247`), `Остаться` (`UnsavedChangesDialog.jsx:45`). `<option>` text is Body's 16px/400, inherited from its select (rule 5). |
| Meta | **12px** (`text-xs`) | 600 for field captions / 400 for hints | **1.33** (16px) | Field captions («Тип», «Идентификатор», «Название» — `text-xs font-semibold`), help text («Только канонический id…»), row meta («Канал · включён») |

**Phase-specific type rules**

1. **PIPEUI-04 — the tab type steps DOWN from `text-3xl` to `text-2xl`.** The section tab must match
   the content `h2` scale exactly, so a tab and the block heading below it share one level. Measured
   target: `font-size: 24px`, `line-height: 32px`. Removing `text-3xl` from `AdminLayout.jsx:13` is
   the change; nothing else in the app changes size.
2. **Weight carries tab state, size carries hierarchy.** Active tab `font-semibold` (600), inactive
   `font-normal` (400). The pre-Phase-22 rule "the active tab carries the former H1 weight" survives
   as weight + an accent underline, no longer as a size jump.
3. **Monospace is a family, not a size.** The ingest id field and the YAML editor stay 16px
   `font-mono`; this is not a fifth size.
4. **Weight 500 is pre-existing, bounded and frozen.** It is the weight of the filled CTA primitives
   this phase merely recolours, and of many untouched controls — it is never a value the phase
   introduces or normalises. The real inventory today, measured: filled CTA labels
   (`ActionButton.jsx:29`, `IngestSourcesSection.jsx:308`,
   `UnsavedChangesDialog.jsx:53`, `AdminPipelineConfigPage.jsx:305`, `AdminDigestPage.jsx:794`/`:919`,
   `LoginPage.jsx:198`, `RegisterPage.jsx:210`); untouched secondary/outline buttons
   (`AdminDigestPage.jsx:554`–`:577`, `:679`, `:786`, `IngestionScheduleSection.jsx:173`/`:213`,
   `AdminPipelineConfigPage.jsx:314`); text links (`font-medium text-primary` / `text-accent`); and
   the `IngestionScheduleSection` field captions (`:169`, `:183`, `:199`, 14px/500). The phase swaps
   *colours* on some of these chains and changes nothing else — it **adds no `font-medium`, removes
   none, and must not promote any of them to 600**. A product-wide weight sweep is not authorised by
   `PIPEUI-01…04`.
5. **`<option>` text is not a separate label size.** `Канал` / `Плейлист` inherit the controlling
   select (`IngestSourcesSection.jsx:270`: `text-base font-normal`), i.e. 16px/400 — always 400,
   because `font-normal` is on the control itself.
6. **Exception (pre-existing, do not restyle):** the schedule time input
   `IngestionScheduleSection.jsx:190` is `text-sm` (**14px**) and its value is `text-ink`, not
   `text-ink-2`. It is in scope only for the `border-rule` / `bg-paper` declarations that already
   exist in its class string; its size and colour are untouched by this phase.
7. No heading becomes italic, no letter-spacing is added, no uppercase is introduced. The only
   removed uppercase text in the product is the «Админ» eyebrow.

### Token contract A — the semantic family (THEME-02, PIPEUI-02)

**This table is the fix for the unreadable «Тип» select.** Every name below is currently used by
admin components and declared nowhere, so Tailwind v4 emits no utility; declaring them is the whole
repair. Declare all six in `@theme static` (dark values) **and** override all six under
`[data-theme="light"]` — every one of them is theme-dependent.

| Token | Dark (`@theme static`) | Light (`[data-theme="light"]`) | Relation to canon | Role |
|-------|------------------------|-------------------------------|-------------------|------|
| `--color-paper` | `#131925` | `#FFFFFF` | equals `--color-bg-surface` in both themes | Card / dialog / field surface |
| `--color-paper-2` | `#1A2233` | `#F1F5F9` | equals `--color-bg-elevated` in both themes | Nested surface |
| `--color-ink` | `#F1F5F9` | `#0F172A` | equals `--color-text-primary` in both themes | Primary text |
| `--color-ink-2` | `#CBD5E1` | `#334155` | **new** — one step below `ink`, above `muted` | Field values, row ids, dialog body, secondary text |
| `--color-muted` | `#94A3B8` | `#475569` | dark equals `--color-text-secondary`; light is deliberately one slate step darker (`#64748B` only reaches **4.34:1** on `paper-2`) | Hints, captions, inactive tab, row meta |
| `--color-rule` | `#2A3548` | `#CBD5E1` | dark equals `--color-border`; **light deviates by design** (`#CBD5E1` vs `--color-border` `#E2E8F0`) — see § Boundary legibility | Panel, row and field borders, tab-strip rule |

|---|---|---|---|---|
| `ink` | 16.06 | 14.52 | 17.85 | 16.30 |

### Boundary legibility — recorded decision for the light `rule`

`border-rule` is **inert today** (the utility does not exist), so every `border border-rule` resolves
to `currentColor` — roughly 16:1 in both themes. Declaring the token *paints* those borders, so the
repair must pick the painted value or it silently weakens every panel, row, field, dialog secondary
button and the tab strip.

| Boundary pair | Canon-parity `#E2E8F0` (light) | **Declared `#CBD5E1` (light)** | Dark `#2A3548` |
|---|---|---|---|
| `rule` on `paper` (`#FFFFFF` / `#131925`) | 1.23 | **1.48** | 1.43 |
| `rule` on `paper-2` (`#F1F5F9` / `#1A2233`) | 1.13 | **1.36** | 1.29 |
| `rule` on `bg-app` (`#F8FAFC`) | 1.18 | **1.42** | — |

**Decision: deviate light `rule` to `#CBD5E1`.** Rationale, recorded so it is not re-litigated:

- The «Тип» select sits on the `paper-2` sub-panel inside a `paper` block. Its **fill step** is
  `#FFFFFF` on `#F1F5F9` = **1.13:1**; with the declared value its **edge** becomes **1.36:1** — the
  border is now more distinguishable than the fill step it is supposed to supplement. Canon parity
  (`#E2E8F0`) gives 1.13:1, i.e. exactly the fill step and no edge at all, which leaves the select
  with no visible affordance in light theme.
- **No declared text ratio changes.** No text token is ever painted on `rule`, so row G-7 of the
  token gate is untouched by this decision; only `rule`'s own value and the G-8 alias row move.
- **Dark `rule` stays canon-parity `#2A3548` (1.43:1).** The failing affordance is the light-theme
  one; changing the dark border would repaint every panel in the primary theme for no requirement,
  so dark is deliberately left at status quo.
- **WCAG 1.4.11 is explicitly known and accepted.** Neither 1.48:1 nor 1.36:1 reaches the 3:1
  non-text threshold. These borders are non-essential decorative separators, not the sole carrier of
  any state: fields additionally carry a fill step and a 44px box, panels additionally carry
  spacing/radius, and the tab strip is reinforced by `border-accent` + 600 weight on the active item.
  ROADMAP criterion 2 ("the select is readable") is a **text** criterion and remains satisfied
  literally; this decision is the honest record that the boundary remains decorative.
- If a future phase wants true 3:1 field edges it needs a dedicated `--color-field-edge` token and a
  baseline reset across all panels — a new decision, out of scope here.

### Token contract B — theme-independent fills (THEME-01, D-05…D-09)

Declare in `@theme static` only. **No `[data-theme="light"]` override for any of these** — identical
value in both themes is the contract (D-08), and the gate pins the *absence* of an override.

| Token | Value | Label token | Measured ratio | Migrates from |
|-------|-------|-------------|----------------|----------------|
| `--color-primary-solid` | `#7C3AED` | `--color-on-solid` `#FFFFFF` | **5.70** | `bg-primary text-text-primary` |
| `--color-accent-solid` | `#0E7490` | `--color-on-solid` | **5.36** | `bg-accent text-accent-ink` |
| `--color-success-solid` | `#15803D` | `--color-on-solid` | **5.02** | `bg-success text-text-primary` |
| `--color-danger-solid` | `#DC2626` | `--color-on-solid` | **4.829** (worst case; 4.83 at 2 dp) | `bg-danger text-text-primary` |
| `--color-on-solid` | `#FFFFFF` | — | — | replaces every `text-text-primary` **on a fill** |
| `--color-voting-ink` | `#0F172A` | — | **9.31** on `--color-voting` `#EAB308` | `bg-voting text-bg-app` |
| `--color-scrim` | `rgba(0, 0, 0, 0.60)` | — | n/a (overlay) | `bg-ink/40`, `bg-text-primary/40` |

**`danger-solid` floor is `>= 4.829`, not `4.83`.** White on `#DC2626` measures **4.82940**; asserting
`>= 4.83` would fail against the declared value's own rounding, so every gate assertion, table and
review note uses **4.829**.

**`--color-scrim` — resolution of the `bg-ink/40` hazard (discretion zone 1).** `ink` is a *text*
colour; once declared, `bg-ink/40` would paint a **40 % white veil** in the dark theme (CONTEXT
hazard) and a black veil in the light theme — the same theme-flip defect the phase is fixing. The
scrim therefore gets its own theme-independent token and **`bg-ink` must not appear anywhere in
`web/src` afterwards.** The same correction applies to the three identical scrims in
`AdminDigestPage.jsx:821`, `:885`, `:948` (`bg-text-primary/40` → white veil in dark today) — see
§ "Same-root-cause addendum" below. This is a class-string swap, not a new surface: four overlay
divs, one class each.

**`--color-accent-ink` is NOT declared (D-10).** All three consumers move to
`bg-accent-solid text-on-solid`. A declared token with zero consumers is exactly the defect class
this phase removes, so the gate also asserts its absence (see § Token-coverage gate, G-5).

### Reader-surface delta (recorded, accepted — CONTEXT.md § Hazards)

`MaterialPage.jsx:187` carries `border border-rule bg-paper-2 text-sm font-medium text-ink`. All three
of those utilities are inert today, so the draft-preview callout currently renders with no fill, no
border and inherited text. After the token declarations it becomes a **painted callout**:
`#F1F5F9` surface + `#CBD5E1` border + `#0F172A` text in light (14px/500 unchanged). **This visible
reader-surface change is accepted and intentional** — it is the unavoidable consequence of making
`paper-2`/`rule`/`ink` real, it is one element, and it adds no new token, no new component and no
reader re-theme. Every other reader-surface utility is out of scope per ROADMAP.

### Surfaces are opaque

`bg-paper-2/40` (`IngestSourcesSection.jsx:219`, `:264`) is promoted to **solid `bg-paper-2`**.
Reason: 40 % of `#F1F5F9` over `#FFFFFF` renders as `#F9FBFC` — a **1.04:1** surface step (≈2 % per
channel), i.e. the nested panel would be invisible in the light theme, and a nested surface that
exists only in one theme is the bug again.
Contract rule: **no `paper` / `paper-2` utility carries an alpha modifier** (pinned by G-6).

**Normative `tabClass` (PIPEUI-04).** Class list order is irrelevant; the set is not:

```
'inline-flex min-h-11 items-end border-b-2 pb-2 text-2xl focus-visible:outline-primary'
  active   → 'border-accent font-semibold text-ink'
  inactive → 'border-transparent font-normal text-muted hover:text-ink'
```

`focus-visible:outline-primary` is added because the tab is the primary control of the section and
currently has no explicit focus treatment. It uses `--color-primary` `#8B5CF6`, **not** accent:
measured **4.05:1** on light `bg-app` `#F8FAFC`, **4.23:1** on light `paper` `#FFFFFF`, **4.53:1** on

adjacent pair, whereas `outline-accent` (`#06B6D4`) is **2.43:1** on white and would ship the
spec's own failing colour. This is the idiom `AdminPipelineConfigPage.jsx:387` already uses
(`focus-visible:outline-primary`), so no new focus style is introduced — colour only, browser default
width.

## Token-coverage Gate (criterion 3 — the RED for the root cause)

**Form: a Node `node:test` contract test, not Playwright.** File:
`tests/unit/test_semantic_token_coverage.js` (auto-discovered by `npm run test:js` via
`scripts/run-unit-js.cjs`). Why a node test: the root cause is a *missing CSS declaration*, so the
cheapest honest assertion is against `web/src/index.css` + `web/src` sources; `test_concept2_canon.js`
